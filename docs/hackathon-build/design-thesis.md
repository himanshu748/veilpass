# VeilPass Landing Design Thesis

Product truth: VeilPass turns a private credential into a public yes or no receipt. A proof should reveal the answer, not the evidence used to calculate it.

Audience: Hackathon judges, credential issuers and privacy-aware people who need an eligibility answer without collecting an identity file.

Desired feeling: Precise, trustworthy and quietly technical.

Primary action: Create a private proof.

Visual concept: A technical instrument wrapped in an editorial conversion page. The private-to-public boundary is shown as a narrow aperture, not described with generic security decoration.

Primary archetype: Technical instrument.

Secondary archetype: Editorial narrative.

Page silhouette: Quiet header, airy two-column hero, full-width interactive proof lab, open comparison rail, oversized tagline reveal, numbered workflow, evidence strip, FAQ, dark final action band and compact footer.

Type strategy: Manrope for every visible surface. Headings use weight 700 at a disciplined modular scale. Technical metadata uses the same family with tabular numerals.

Material and color language: True-white canvas, near-black ink, flat pale gray-blue bands, midnight violet for private state and verified green for the public receipt. One-pixel rules, restrained Tailwind radii and almost no shadow.

Media strategy: The working product interface is the evidence. No stock photography, fake logos, invented metrics or testimonials.

Signature moment: Violet private signals pass through a thin vertical aperture and emerge as one green public result. The page repeats the same idea in a word-by-word reveal: “Share the answer. Keep the evidence private.”

Runtime honesty: The Compact 0.31.1 contract is real and compiled. The browser is labeled “Local proof mode” until a funded Lace wallet, deployed contract address, proof server and Midnight.js adapter are wired to Preprod.

Three cliches to avoid: Gradient-card hero layouts, generic bento grids and glassmorphism.
